## Current request and transport rules

- Every new submitted request needs a syntactically valid email or phone, following the owner's explicit reply: "any estimate would have to have a contact of some sort". Names alone do not provide a callback channel. Missing/malformed contact returns 422 before any quote, lead or request row is written. The browser retains the editable details across reload. Email or phone ownership/delivery is not verified by this gate.
- Owner preview is read-only and requires no customer callback. Public and authenticated submissions use the same approval, complete-scope, contact, persistence and customer-output boundaries.
- Nonempty `explicitUnknowns` or untriaged `context` requires review. A supplied `serviceRequest` must match the saved offering's display name; extra or different prose requires review. Unrecognized request-envelope fields also require review, rather than silently dropping supplied scope. No classifier decides that text is harmless logistics. Thus even a gate-access note currently requires review. Empty context/unknowns and the known service label do not suppress supported quotes.
- The whole-request review gate runs before the engine. Its internal record explicitly has `internalResult: null` and an application review reason, rather than pretending an engine calculation happened. Original submitted details and the selected price-book snapshot are retained in the transaction.
- JSON transport accepts valid UTF-8, including a leading UTF-8 BOM. Every numeric token must round-trip to the same decimal value before parsing can lose its spelling. This is decimal fidelity, not binary exactness: 0.1 is allowed. Strings are not scanned as numbers. Duplicate object keys are rejected, including escaped equivalent names. Monetary unit/fixed-charge and safe-cent limits are still validated separately. No commercial markup cap was added.
- Authorized same-origin browser catalog GETs may use `Sec-Fetch-Site: same-origin` plus the Referer origin when Origin is absent. The exact tenant allowlist still applies; a supplied Origin always wins. POST still requires Origin. Host and forwarded headers confer no authorization. These are browser-origin controls, not authentication against arbitrary non-browser HTTP clients.
- A successful submission is a committed receipt. Exact retries recover the historical immutable response; rate, tax or approval changes require a new request to calculate again. Definitive 400/401/403/404/409/413/415/422 failures restore the editable form; transport failures, timeouts, server failures and 429 retain the original request for retry. New submissions above the server's 1 MiB limit are caught before sending; old cached pending requests can still receive server rejection and recover.
- The customer displays the engine's safe partial-option notice. All-review configurations still release no price. CRM lead routes are available to authenticated existing owner/staff roles on Operator; calculation/pricing stays QuoteDone/Scale gated. This does not grant additional seats or provisioning rights.
